# Kernel Deck

여러 AI CLI를 한 화면에서 실행하고 관리하는 로컬 터미널 작업대입니다. Windows용 배포본에는 Node.js가 포함되어 있습니다. 사용하는 AI CLI와 해당 서비스의 로그인은 별도로 필요합니다.

## Windows 배포본 실행

1. GitHub Releases에서 `Kernel-Deck-1.0.0-windows-x64.zip`을 내려받고 **압축을 풉니다**.
2. 압축을 푼 폴더의 `start.cmd`를 실행합니다.
3. 브라우저의 `http://127.0.0.1:4317`에서 **새 세션**을 누르고 AI, 작업 폴더, 세션 이름을 지정합니다.

설치 관리자나 관리자 권한이 필요하지 않습니다. Windows 10 1809 이상에서 사용하는 ConPTY 기반이며, 실제 검증 환경은 Windows 11 x64 / Node 24입니다. 배포본은 서명되지 않은 ZIP이며 자동 업데이트는 없습니다.

브라우저를 닫아도 서버와 세션은 계속 실행됩니다. 완전히 끝내려면 `stop.cmd`를 실행합니다. 이 명령은 해당 관리 서버가 소유한 세션도 종료합니다. 실행 로그와 설정은 배포 폴더의 `.data`에 저장되므로 쓰기 가능한 폴더에서 실행하세요. 업데이트 시 기존 서버를 `stop.cmd`로 종료한 뒤 `.data`를 새 배포 폴더로 복사하면 설정을 이어갈 수 있습니다.

## 할 수 있는 일

- Codex, Claude Code, Gemini CLI, Ollama 설치 위치 탐색. PowerShell, Python, WSL 프리셋 및 직접 명령 설정.
- 최대 16개 동시 실행과 초과 작업 대기열. 한 화면에서 최대 4개 터미널 비교 또는 한 세션 집중 보기.
- AI별 직접 입력, 한글, 방향키, Ctrl+C, 터미널 크기 조절.
- 이름·그룹 검색, 실행 상태 필터, 개별 시작·종료·재시작, 전체 종료.
- 브라우저 새로고침·재연결 후 동일한 실행과 출력 복구. 최근 실행의 터미널 기록 내려받기.
- 기존에 열린 AI 프로세스의 PID와 시작 시각 확인. 이 목록은 **관찰 전용**이며 외부 터미널을 인수하거나 종료하지 않습니다.

세션의 **종료**는 해당 프로세스 트리를 강제 종료합니다. 작업을 저장하거나 정상 종료할 기회를 주려면 먼저 터미널 안에서 CLI의 종료 명령 또는 **Ctrl+C**를 사용하세요. **재시작**은 같은 설정으로 새 프로세스를 실행합니다. AI 대화를 이어가는 기능은 각 CLI의 `resume` 등 인수로 직접 지정합니다.

출력이 잠시 없다는 이유로 입력 대기 상태를 추정하지 않습니다. `실행 중`은 프로세스 생존 상태를 뜻합니다. 실행 한도를 낮춰도 이미 실행 중인 세션을 종료하지 않으며, 빈 슬롯이 생기면 대기열을 진행합니다.

## 실행 명령 지정

`실행 파일`과 `인수`는 별도입니다. 인수는 **한 줄에 하나씩**, 경로를 둘러싼 불필요한 따옴표 없이 입력하세요. 예를 들어 Python은 실행 파일 `python.exe`, 인수 두 줄 `-u`와 `C:\work\agent.py`로 실행합니다. 작업 폴더는 존재하는 절대 경로를 사용합니다. API 키는 인수 대신 각 CLI의 기존 로그인 설정을 사용하세요.

Windows `.cmd`, `.bat`, `.ps1` 파일은 PowerShell 같은 셸을 통해 실행해야 합니다. 설치 탐색 프리셋은 이 처리를 포함합니다. 직접 입력할 때는 실행 파일을 `powershell.exe`로, 인수를 `-NoLogo`, `-NoExit`, `-Command`, `& 'C:\path\tool.cmd'` 네 줄로 지정할 수 있습니다.

WSL 프리셋에서 기본 배포판의 셸을 열고 그 안에 설치한 AI 명령을 실행할 수 있습니다. Ollama는 사용자가 설치한 모델명을 인수 `run` 다음 줄에 지정합니다. GPU 사용량, 모델 다운로드, Jupyter 커널 프로토콜, AI 계정·결제 관리는 제공하지 않습니다.

## 저장과 복구

- `.data/state.json`: 세션 설정과 상태, 동시 실행 한도. 저장은 임시 파일 후 교체합니다.
- `.data/logs/`: 세션별 최근 실행 기록, 각각 최대 1 MiB. 재시작하면 해당 세션의 이전 실행 기록을 교체합니다. 터미널에는 최대 5,000줄을 표시합니다.
- 관리 서버 재시작 후 과거 `실행 중`/`대기 중` 상태는 `중단됨`으로 표시합니다. 이전 PID를 다시 제어하거나 작업을 자동으로 재실행하지 않습니다. 필요하면 관찰 전용 목록에서 잔여 프로세스를 확인하세요.
- 손상된 설정 파일은 보존하고 시작 오류를 표시합니다. 백업 복원 또는 파일을 다른 위치에 보관한 뒤 새로 시작할 수 있습니다.

터미널 출력과 실행 인수에는 작업 내용이 포함될 수 있습니다. `.data`는 로컬 저장소에만 남으며 Git 및 배포 패키지에서 제외됩니다. 앱은 AI 서비스로 별도 요청을 보내지 않습니다. 사용자가 실행한 CLI가 해당 서비스에 연결합니다.

## 소스에서 실행

Node.js 22 이상 및 npm이 필요합니다.

```powershell
npm ci
npm run build
npm start
```

`http://127.0.0.1:4317`을 엽니다. 콘솔에서 Ctrl+C를 누르면 관리 서버와 소유 세션을 정리합니다. 백그라운드 실행은 `start.cmd`, 종료는 `stop.cmd`를 사용합니다.

```powershell
# 다른 포트 (동일 .data로 서버를 두 개 실행하지 마세요)
.\scripts\start-manager.ps1 -Port 4318
.\scripts\stop-manager.ps1 -Port 4318
```

`PORT`와 `KERNEL_DECK_DATA_DIR` 환경 변수로 서버 포트와 저장 폴더를 바꿀 수 있습니다. 앱은 `127.0.0.1`에만 바인딩하며 Host/Origin 검사, HttpOnly·SameSite 쿠키, JSON 요청 제한을 적용합니다. 외부 네트워크나 프록시에 노출하는 용도로 설계하지 않았습니다.

## 검증 및 패키징

```powershell
npm run build
npm test
npx playwright install chromium
npm run test:e2e
npm run test:cli
npm run package:windows
npm run test:package
```

테스트는 별도 임시 데이터 폴더를 사용합니다. 엔진 테스트는 실제 PTY 입력과 자식 프로세스 종료, 실행 대기열과 복원을 검증합니다. HTTP/WebSocket 테스트는 세션 제어와 요청 접근 경계를 확인합니다. 브라우저 테스트는 3개 실제 터미널의 입력 분리, 새로고침, 크기 변경, 상태 제어와 자동 재연결을 확인합니다. CLI smoke 테스트는 설치된 AI CLI 버전 출력과 실제 시작 화면만 확인하며 모델 요청이나 로그인 선택을 자동으로 보내지 않습니다.

패키징은 Windows x64에서 실행하며 `artifacts/release/`에 ZIP과 SHA-256 체크섬을 만듭니다. 소스·빌드 결과·필수 서버 의존성·현재 Node 런타임·라이선스만 명시적으로 포함합니다. Linux 경로는 일부 단위 테스트에 포함되어 있으나 Linux 배포본은 제공하지 않습니다.

브라우저 테스트는 Playwright Chromium을 우선 사용하고, 없으면 설치된 Chrome 또는 Edge의 격리된 headless 프로필을 사용합니다. 기존 브라우저 탭이나 로그인 프로필은 사용하지 않습니다.

구현 참고: [node-pty](https://github.com/microsoft/node-pty), [xterm.js](https://xtermjs.org/docs/), [Windows ConPTY](https://learn.microsoft.com/en-us/windows/console/pseudoconsoles).
